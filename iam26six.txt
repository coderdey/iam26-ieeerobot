Error 1: Wrist Camera USB Disconnect

The USB device /dev/video2 physically disappeared mid-recording. The wrist camera cable is coming loose as the arm moves. You already figured this out — reinforcing the cable fixed it.

Permanent fix: Secure the wrist camera USB cable with:
- Cable clips along the arm
- A strain relief loop near the base (leave slack so the cable doesn't pull taut when the arm extends)
- Tape the USB connector at the laptop end so it can't wiggle out


Error 2: Gripper Servo Overload (the bigger one)

Motor ID 6 = gripper. Your teammate closed the leader gripper fully, which made the follower gripper stall against the object (or against itself). The servo drew too much current, triggered its overload protection, and killed the entire serial bus — all 6 motors share one daisy-chain, so one servo's overload error corrupts communication for all of them. That's why the arm "lost connection completely."

Your teammate's fix was exactly right — close the gripper just enough to grip, never fully. This is a known issue with Feetech STS3215 servos.


Permanent fixes for the gripper overload:

1. Soft gripper pads — add rubber/silicone pads to the gripper fingers. This gives compliance so the servo doesn't stall against a rigid surface. (Rules allow custom contact pads — rule 5.1.2.2)
2. Limit gripper range in software — you can set a max position limit so the gripper can never fully close:
from scservo_sdk import PortHandler, PacketHandler
ph = PortHandler("/dev/ttyACM1")
ph.openPort()
ph.setBaudRate(1000000)
pk = PacketHandler(0)
# Set minimum position limit for gripper (motor 6)
# Adjust the value so it stops before stalling
pk.write2ByteTxRx(ph, 6, 9, 1800)  # CW angle limit — experiment with value
3. Tell your teammate the rule of thumb: grip just firm enough that the object doesn't slip. If the leader gripper handle hits its mechanical stop, the follower is probably overloading.
